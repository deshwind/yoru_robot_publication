# Offline extensions: deployment thresholds, sustained-confirmation rule, outcome vs truth

Generated by `evaluation/scripts/offline_extensions.py` from 300 world-mode runs (A ×20, A-V ×20, B ×20, B-C7 ×20, C ×20, D ×20, E ×20, F-pen ×20, F-straw ×20, G ×20, H ×20, I ×20, J ×20, K ×20, L ×20), 490231 logged person-frames. Manifests: `evaluation/data/manifest.csv`.

## Validation against the logs

1. Baseline values (device 0.6, override 0.75) reproduce the logged online values: C mismatches **0**, C7 risk (after override) mismatches **0**, decision mismatches **0**, of 490231 frames.
2. Seeded noise replay: dropout counts match every heartbeat in **300 / 300** runs. The logged D values equal the replayed scores above 0.6 bit for bit and in order in **295 / 300** runs, and are an exact ordered subsequence of them in **300 / 300** runs (36960 values compared). The 7 replayed values missing from the logs (in 5 runs) have no logged counterpart; this is consistent with injected devices the node did not associate with a person in that frame (C2 false, independent of the thresholds), not verified frame by frame. 204 logged values come after the final 1 Hz heartbeat and are not replayed. Note: `recv_stamp` has the /clock resolution (0.1 s), so replay order uses the camera header stamp. Details: `noise_replay.csv`.
3. Baseline FSM replay ("S1 = first confirmed frame + 5 s") vs the real FSM: **300 / 300** runs agree (same escalation, S1 within 0.15 s).

## 1. Deployment thresholds (device_confidence = override = 0.3, yoru_real.yaml)

**Can C7 ever block a confirmation?** No. Confirmation requires C2, which requires a device with D > device_confidence = 0.3; any such device has D ≥ override = 0.3, so a "high" risk is always overridden. In the logs: 32385 frames had a confounder at the mouth; 5460 of them had C2 and were still blocked by C7 at the baseline values; under the deployment values **0** remain blocked.
