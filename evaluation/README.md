# Simulation evaluation: reproduction guide

How to reproduce every simulation run, metric and table of the evaluation from a clean machine.
Results and evidence are in [`../evidence/README.md`](../evidence/README.md). The audit of the
system under test is in [`../docs/sim_audit.md`](../docs/sim_audit.md).

## 1. Environment

| Component | Version used |
|---|---|
| OS | Ubuntu 22.04 |
| ROS 2 | Humble (apt): `ros-humble-desktop`, `ros-humble-navigation2`, `ros-humble-nav2-bringup`, `ros-humble-slam-toolbox`, `ros-humble-gazebo-ros-pkgs`, `ros-humble-gazebo-ros2-control`, `ros-humble-ros2-control`, `ros-humble-ros2-controllers`, `ros-humble-twist-mux`, `ros-humble-vision-msgs` |
| Gazebo | 11.10.2 (classic) |
| Python | 3.10, packages pinned in [`requirements.txt`](requirements.txt) |

```bash
pip install -r evaluation/requirements.txt
bash evaluation/scripts/configure_paths.sh        # only if not cloned to ~/Yoru_bot_publication
python3 -c "from ultralytics import YOLO; YOLO('yolov8n.pt')"   # downloads the COCO weights here
source /opt/ros/humble/setup.bash
colcon build --symlink-install          # 4 packages incl. yoru_sim_plugins (Gazebo actor plugin)
source install/setup.bash
```

Do **not** source `ros_network.env` for evaluation runs: it points DDS discovery at the robot's
Raspberry Pi. The batch runner gives each run its own `ROS_DOMAIN_ID` and clears the
discovery-server variables.

## 2. What a run is

| Item | Where |
|---|---|
| World | `src/yoru_bringup/worlds/eval_two_room.world`, generated by `scripts/make_eval_world.py`: the demo world plus 3 plugin-driven people and 1 intruder, each with a lidar-visible body |
| Robot base | room B (−4.0, 1.5, 0), about 6 m via the doorway to the cctv1 camera spot (1.8, 0) ([`config/eval_launch.yaml`](config/eval_launch.yaml)) |
| Timings | research brief: S0 5 s, S1 3 s, S2 ≤ 90 s, S3 3 × 8 s (cap 30 s), S4 2 s, reset 10 s, target lost 8 s, SAFE_STOP < 0.35 m for 0.4 s, cooldown 60 s ([`config/eval_base.yaml`](config/eval_base.yaml)) |
| Perception | YOLOv8n on the Gazebo CCTV images (real), plus injected device/support detections attached to the violator (`scenario_publisher_node` `mode: world`), detector noise σ = 0.05, dropout 5 %, bbox jitter 3 px |
| Human behaviour | `human_actor_node`: seeded start positions and violator, compliance after a heard warning, step back, departure, wander, intruder, admin override |
| Clock | all decision timing on sim time (`use_ros_clock:=true`) |
| Scenarios | [`scenarios/*.yaml`](scenarios/): A, A-V, B, B-C7, C, D, E, F-pen, F-straw, G, H, I, J, K, L |

Parameter precedence per node: `yoru_sim.yaml` → `config/eval_base.yaml` → `scenarios/<id>.yaml`
→ per-run values (seed, scenario id, incident log folder) → launch overrides (weights, threshold).
Each run's merged file is saved as `<run_dir>/overlay.yaml`.

## 3. Running

```bash
# pilot (Phase 4): Scenario A, seeds 0-2
python3 evaluation/scripts/run_batch.py --scenarios A --seeds 3 \
    --out evaluation/data/pilot --manifest evaluation/data/pilot/manifest.csv

# full baseline: all scenarios x 20 seeds (about 300 runs, roughly 9-10 h)
python3 evaluation/scripts/run_batch.py --scenarios all --seeds 20 --skip-existing

# a weight / threshold configuration (tag derived from the values)
python3 evaluation/scripts/run_batch.py --scenarios A,G --seeds 20 \
    --w-d 0.5 --w-p 0.25 --w-t 0.15 --w-s 0.10 --threshold 0.6
```

`--skip-existing` resumes an interrupted batch. `--dry-run` lists the planned runs.

Each run writes `<out>/<tag>/<scenario>/<seed>/` containing `overlay.yaml`, `launch.log`,
`bag/` (rosbag2, sqlite3), `incident_logs/incidents.jsonl` and `run_info.json`, plus one row in
the manifest CSV: scenario, seed, weights, status, outcome, stage, sim time of the outcome, expected
outcome, ground truth, wall start/end, RTF, attempts, bag check, processes that died, and the
SHA-256 fingerprint of `src/` + configs.

A run stops 10 s (sim) after the FSM's outcome, or at the scenario's `max_sim_s` if it never
escalates. The runner checks that the overlay was applied (`config_not_applied`), stops the
whole process group (SIGINT, then SIGTERM, then SIGKILL) and verifies nothing survived
(`cleanup_failed`). Start-up failures are retried once.

Summarise any bag: `python3 evaluation/scripts/bag_summary.py <run_dir>/bag`.

## 4. Metrics and tables (Phase 5)

```bash
python3 evaluation/scripts/extract_metrics.py            # -> evaluation/data/metrics.csv (one row per run)
python3 evaluation/scripts/summarise.py                  # -> evaluation/results/{continuous,rates,outcomes}.csv,
                                                          #    tables.md, tables.tex
```

`extract_metrics.py` reads every run in the manifest with `rosbags` (no ROS needed) and computes the
brief's metrics; a metric that does not apply is left empty. The definitions are in the script's
docstring and in `evidence/README.md` (Phase 5). `summarise.py` gives per-scenario
mean ± SD, median [IQR], bootstrap 95 % CI of the mean, and Wilson 95 % CI for every rate.

Batch progress while it runs: `grep -c status= evaluation/data/baseline_batch.log` (of 300).

## 5. Tests

```bash
PYTHONPATH=src/yoru_core:$PYTHONPATH python3 -m pytest src/yoru_core/test -q   # system (82)
python3 -m pytest evaluation/tests -q                                           # statistics (8)
```

## 6. Scripts

| Script | Purpose |
|---|---|
| `run_batch.py` | batch runner (Phase 4) |
| `bag_summary.py` | human-readable summary of one bag |
| `check_run.sh` | one run with a hand-written overlay (Phase 3 checks) |
| `make_eval_world.py` | regenerates the evaluation world |
| `configure_paths.sh` | points the simulation configuration at the clone's location |
| `resume_baseline.sh` | resume the baseline batch after a stop (skips valid runs, rebuilds results at the end) |
| `make_results.sh`, `after_batch.sh` | build all Phase 5–6 results and figures (optionally once a running batch exits) |
| `make_figures.py` | paper figures (PDF + PNG): outcomes, escalation timeline, metric distributions, threshold sensitivity |
| `phase0_*.py`, `phase1_*`, `phase2_*` | evidence generators for those phases |
| `extract_metrics.py`, `summarise.py` | Phase 5 metrics and tables |
| `sensitivity_offline.py` | Phase 6: offline weight/threshold sensitivity from the logged frames → `evaluation/results/sensitivity/` |
